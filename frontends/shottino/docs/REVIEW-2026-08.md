# shottino — review remediation plan (2026-08-01)

Produced from a five-lens code review (security, concurrency/memory, logic,
parsers, style) of the whole frontend. Every item below was **verified
against the code**, not inferred: file:line references are to the tree at
`c6c69ea0`, and where a line has moved the surrounding function name is
given so it can still be found.

Two items are already **DONE** (`f2ebca7c`) and are recorded here only so
the list reads as a complete account of what the review found.

## How to work this list

- **Order matters.** Work the phases in order. Phase 1 items are silent
  corruption; Phase 2 items are visible misbehaviour; Phase 3 is hardening;
  Phase 4 is style. Within a phase, order is by cost-to-fix ascending.
- **One logical change per commit**, message explains WHY. The gate is
  `make check` — 14 suites, zero warnings, no exceptions.
- **TDD where the bug is observable.** Several items below name the test
  that should fail first. Where a bug can only be seen through a live
  terminal or a live socket, say so in the commit rather than pretending a
  test covers it.
- **Do not batch unrelated fixes.** Two of these (P1.1, P1.2) touch the
  same file within a hundred lines of each other and are still two commits.

## Phase 1 — silent corruption — **DONE** (1a7a6054, 75255fbf, 2dbd59bb, 9e7fbdd8)

All four landed, each with its own commit and, where a property could be
observed deterministically, its own test. Kept below as the record of what
was wrong and why the fix is shaped the way it is.

These produce wrong state with no error message. They are ranked above
things that crash, because a crash tells you it happened.

### P1.1 — DONE — The WebSocket is written from three threads with no lock

**Where:** `ws_send_frame`, shottino.c:4074 (`conn_write_all(&app->ws, …)`).
**Writers:** main (heartbeat 5313, pong 4304, joins 4264, the whole command
dispatcher 11586+), worker (`join_channel_on` → `ws_join` 7992,
`close_query_target` → `ws_push_user` 8038, `ctcp_respond` 2404), llm thread
(`tool_execute` → `ws_push_user` 7276).

**Why it corrupts:** OpenSSL forbids concurrent use of one `SSL*`. Two
threads inside `SSL_write` corrupt its internal state; without TLS, two
`conn_write_all` loops interleave partial writes and corrupt WebSocket
framing. Worse, `ws_try_reconnect` (5291) calls `conn_close` — `SSL_free`
plus `memset` — on main while a worker may be mid-write on that object: a
cross-thread use-after-free.

**Fix:** add `app->ws_lock` (a plain mutex, NOT `app->lock` — the frame
build must not sit under the UI lock) held across the whole of
`ws_send_frame` and across `conn_close`/reconnect in `ws_try_reconnect`.
Take it *after* `app->lock` anywhere both are needed, and document that
ordering next to the declaration; the ircd bridge already sets this
precedent (`ircd.lock`, shottino.c:13099).

Also unsynchronized on the same object and fixed by the same lock:
`app->ws_ref` (incremented from all three threads at 4152, 4165, 5313 —
duplicate refs are possible today), `app->ws_connected`,
`app->ws_user_join_ref` (rewritten on reconnect at 4264 while the worker
reads it at 4168).

**Alternative worth considering first:** funnel every non-main send through
the job queue so only main touches the socket. Fewer moving parts, but it
changes the latency of `/whois` and friends — measure before choosing.

**Test:** none possible in-process without a fake socket; state the
reasoning in the commit. The stale comments that say "the socket thread"
(there is no WS thread — the WS is pumped on main from `event_loop`) should
be corrected in the same commit, since they are what hid this.

### P1.2 — DONE — `clear_matching_pending_echo` desynchronizes the log arrays

**Where:** shottino.c:1263-1275.

Six arrays are parallel-indexed (`log`, `log_mentions`, `log_pending`,
`log_ids`, `log_media`, `log_scope`). This function memmoves **three** of
them. `log_shift_locked` (1116) and `log_row_move_locked` (1127) correctly
move all six.

**Effect:** after every echo retirement — i.e. after every message you send
while its echo is on screen — every row above the deleted one carries
another row's scrollback id, inline-image slot and window scope. The unread
divider lands on the wrong row; an image renders under the wrong message;
rows file into the wrong window's scope. Cumulative, in a hot path.

**Fix:** call `log_row_move_locked` in a loop instead of hand-rolling the
memmoves, so there is one place that knows how many arrays there are. That
is the root-cause fix: a seventh array added tomorrow must not need this
site edited again.

**Test:** append rows with distinct ids/scopes, retire a pending echo from
the middle, assert every surviving row still carries its own id and scope.

### P1.3 — DONE — The llm thread is never stopped or joined

**Where:** `app->llm_stop` is declared (939) and read (7521, 7523) and
**never assigned anywhere**. `main` joins only the worker (14750), then
frees every log line, destroys `app->lock`, frees `app->ssl_ctx` and
`free(app)`.

**Effect:** the llm thread is either blocked in `pthread_cond_wait` on a
condvar that gets destroyed, or mid-turn — a call that by design takes
seconds to minutes — after which it calls `log_line` on a destroyed mutex
and `SSL_new` on a freed `SSL_CTX`. Use-after-free in the window before
process exit.

**Fix:** in the shutdown path, set `app->llm_stop = true` under the llm
queue's lock, broadcast the condvar, and `pthread_join(app->llm_thread)`
guarded by `app->llm_thread_started`. An in-flight turn should be allowed
to finish or be abandoned explicitly — decide which and say so in the
comment; do not leave it implicit.

### P1.4 — DONE — `app->input` is written from two threads, and can write one byte OOB

**Where:** locked writers — `stt_job` (10598, worker), `reply_to` (8620),
the `/kill` prefill (8665). Unlocked writers — `event_loop` keystroke path
(14317-14321), `handle_enter` (12379), `complete_input` (9072),
`history_prev`/`history_next` (8221).

**Effect:** main evaluates `app->input_len + 1 < sizeof(app->input)` with a
small length; `stt_job` then sets `input_len` near the maximum; main
resumes and writes at the old-checked index, then `input[input_len] = 0`
writes one byte past the array into the adjacent `input_len` field. Plus
ordinary transcript/keystroke interleaving corruption.

**Fix:** take `app->lock` around every read-modify-write of
`input`/`input_len`. The keystroke path is the hot one; it is still only a
mutex per keypress.

## Phase 2 — visible misbehaviour — **DONE** (0716f3b0, 221992dc, 0bbde06a, 005792a7, 71e63517, 7e041be2, 4a2a86bf, 357b8ffe, a4a0310a)

Every item landed. Two things turned up while working it that were not in
the review: `/preview-ascii` was invisible to the verb scanner (it stopped
at the hyphen), and three MCP shim tests had been written and never
registered, so the door every tool reaches the claude CLI through had no
running test. Both are fixed with the items they surfaced next to.

### P2.1 — DONE — Non-ASCII cannot be typed

**Where:** `event_loop`, shottino.c:14319 — `isprint(ch)` filtering bytes
from `getch()`. `setlocale(LC_ALL, "")` is called (14219) but `get_wch` is
never used.

**Effect:** in any UTF-8 locale `isprint()` is false for every byte ≥ 0x80,
so typing `perché` sends `perch`. For a client aimed at an Italian network
this is the most user-visible defect in the review. Backspace (14318) also
deletes one **byte**, so UTF-8 arriving by another route — an `/stt`
transcript, the reply-prefill guillemets `«»`, a completed non-ASCII nick —
becomes an invalid half-sequence after one Backspace and is sent as such.

**Fix:** switch the input path to `get_wch()`; keep the buffer UTF-8 and
encode the wide char on the way in (`wcrtomb`), or accumulate bytes and
validate. Backspace must delete one **character**: walk back over
continuation bytes (`0x80..0xBF`). `iswprint()` replaces `isprint()`.

**Also fixed by this:** `isprint(ch)` is called with values > 255 for
unhandled function keys, which is undefined behaviour (an out-of-range
ctype table read).

**Test:** feed a UTF-8 sequence through the input-handling function and
assert the buffer holds the whole character and that one Backspace removes
all of its bytes. `tests/test_keys.c` is the natural home.

### P2.2 — DONE — `/w N` reads past the end of the string

**Where:** shottino.c:12347 (in the `/window`|`/win`|`/w` arm).

```c
const char *arg = line[2] == 'w' && line[3] == ' ' ? line + 3
                : (line[4] == ' ' ? line + 5 : line + 8);
```

For `/w 3` index 2 is the space, so the first test fails; index 4 is the
NUL, so the second fails; `arg = line + 8` — four bytes past the
terminator, into whatever `alias_expand` left in the stack buffer. Usually
`atoi` garbage yields 0 and nothing happens; occasionally a valid number
jumps to an arbitrary window. `/win` and `/window` are correct. The first
ternary arm is dead for every spelling (nothing has `'w'` at index 2).

**Fix:** parse this the way the rest of the dispatcher does — match the
verb, then skip the verb and the spaces. Do not repair the ternary; replace
it.

**Test:** `/w 2`, `/win 2`, `/window 2` all focus window 2.

### P2.3 — DONE — Bare `/whois` and `/whowas` silently run `/who`

**Where:** the `/whois ` arm (11589) requires a trailing space and
argument; without them the line falls to `strncmp(line, "/who", 4)` (11603),
whose target is `line + 5` — `"s"` for `/whois`, `"was"` for `/whowas`.

**Fix:** match the bare forms explicitly and print usage. Root cause is
prefix matching without a word boundary; check the other `strncmp` arms in
the same dispatcher for the same shape while you are there (`an_oper_verb_is
_matched_as_a_whole_word` in test_windows.c shows the pattern the oper verbs
already use — reuse it).

### P2.4 — DONE — `/join #chan key` sends the key inside the channel name

**Where:** shottino.c:11511 puts the whole remainder in `job.channel`;
`join_channel_on` (7978) POSTs `{"name":"#chan key"}`. The server takes the
key as a **separate `key` param**
(`lib/grappa_web/controllers/channels_controller.ex:145`) and validates the
name, so a keyed join fails with `join failed HTTP 400`. `/help join`
advertises `/join #chan [key]`.

**Fix:** split on the first space, send `key` as its own field. Check
`struct job` has somewhere to carry it before assuming.

### P2.5 — DONE — Enter on `llm.prompt` in the settings panel truncates the prompt

**Where:** `setting_value` renders `llm.prompt` as `%.120s` (7644);
`panel_key`'s Enter (9186) prefills `/set llm.prompt <that text>`; a second
Enter writes the truncation back.

**Fix:** the panel must not prefill a value it displayed truncated. Either
prefill from the raw value (now available — `setting_raw`, added in
`f2ebca7c`) or refuse to prefill and open the `@file` form instead. Tokens
already take the refuse path (9182-9187); this should match it.

**Test:** set a >120-char prompt, drive the panel's Enter, assert the stored
prompt is unchanged.

### P2.6 — DONE — A recording error path can close stdin and kill the keyboard

**Where:** `record_start_for` (10686) `memset`s `struct rec`, setting
`stdin_fd = 0`; the "idle is -1" invariant is only restored by
`record_cleanup`'s own memset (10635). If `pipe()` (10722) or `fork()`
(10731) fails, `record_cleanup` runs with `stdin_fd == 0` and its
`if (stdin_fd >= 0) close(...)` closes the process's stdin. `getch()` then
returns ERR forever.

**Fix:** set `stdin_fd = -1` explicitly after the memset (and anywhere else
the struct is zeroed), or make the sentinel 0-safe by tracking a separate
`has_stdin` bool. The first is simpler and matches how the field is read.

### P2.7 — DONE — Oversized AGENT.md silently truncates and drops every memory

**Where:** `bot_effective_prompt` (7162) freads AGENT.md into the 16 KiB
`cfg.prompt` with no size check; `bot_memories_append` (7152) is then left
one byte of room and appends nothing. `/bot show` still counts the notes.

**Fix:** refuse (or truncate loudly) the way `/set @file` already does
(12138-12141) — that path prints "larger than N bytes — refusing a
truncated prompt" and is the precedent to copy. Reserve the memories'
budget before reading AGENT.md.

## Phase 3 — security and robustness

Ordered by (likelihood × blast radius), not by CVSS instinct.

### P3.1 — The account password is a command-line positional

**Where:** `main` — `expected = 3` (14547), `password = positional[2]`
(14622), and `print_usage` documents
`shottino https://grappa.example.net vjt hunter2`.

Any local user reads it from `/proc/<pid>/cmdline` or `ps` for the whole
life of the process, and it lands in shell history.

**Fix:** read from `SHOTTINO_PASSWORD` (the `--ircd` bridge already does
exactly this with `SHOTTINO_IRCD_PASS`, 14032 — copy that shape), or prompt
on a tty when the positional is absent. Keep the positional working with a
deprecation line on stderr for one release; do not break existing
invocations silently.

### P3.2 — `--dangerously-skip-permissions` is unconditional

**Where:** shottino.c:6671, always passed to the claude CLI. Contained
today only because our tools ride MCP and `--tools ToolSearch` suppresses
the built-ins — and the comment at 6674-6685 records that this flag's
semantics already changed between CLI versions.

**The live path:** `/set llm.cli_tools Bash` (a supported setting) plus
`/bot on` means any stranger who mentions the bot reaches a CLI with
permissions disabled. `bot_consider`'s only filter is "owner or mentioned".
**Note this became reachable with `f2ebca7c`** — before that fix the bot
never ran at all.

**Fix, in order of preference:** (1) drop
`--dangerously-skip-permissions` and wire `--permission-prompt-tool` to a
real handler that consults `tool_permitted`; (2) failing that, refuse to
pass `cli_tools` at all when `bot_enabled` is on, so the network can never
provoke a turn that reaches the CLI's own tools. The existing warning
(12193) stays either way, but a warning is not a control.

### P3.3 — Bot grants are keyed on an unauthenticated nick

**Where:** `bot_has_grant` (6789) matches with `irc_name_eq` and nothing
else, while `bot_sender_is_owner` (6768) correctly demands services auth
(`account[0]` or `registered`).

A persisted grant for `alice` is honoured for whoever holds that nick
weeks later.

**Fix:** store the account name alongside the nick and require it to match;
a grant given to an unregistered nick should be session-only (never
written to the grants file). Say so in `/approve always`'s confirmation so
the user knows which kind they got.

### P3.4 — `die()` from a background thread on a transient HTTP failure

**Where:** `http_request_raw` — 1688 (connect failed), 1706 (write failed),
1713 (bad response). Called from `worker_main` jobs (8072) and the llm
thread.

A bouncer restart during any queued REST call exits the whole client, and
`die()` (1006) never calls `endwin()`, so the terminal is left raw. The WS
path handles the same blip with backoff and reconnect; the comment at
14704 claiming "REST send/fetch still works" becomes a lie.

**Fix:** return `{ok=false}` and let each call site report. Malformed-reply
-as-fatal may stay deliberate for the login path only — if it does, it
must be a distinct call, not the shared one. Add `endwin()` to `die()`
regardless.

### P3.5 — `conn_open_to` leaks an fd and an SSL object on handshake failure

**Where:** 1562-1585 returns false after `connect_tcp` succeeded but
`SSL_new`/`SSL_set1_host`/`SSL_connect` failed. `http_fetch` compensates
with `conn_close` (9337); the `/llm` path (6495) and `/stt` path (10460) do
not — each failed handshake to a misconfigured endpoint leaks an fd until
exhaustion takes down unrelated I/O.

**Fix:** clean up inside `conn_open_to`, per the project's boundary rule
(the function that raised the error owns the cleanup). Remove the now-
redundant compensation at the one call site that has it.

### P3.6 — No `O_CLOEXEC` anywhere; children inherit every fd

**Where:** zero occurrences of `O_CLOEXEC`/`FD_CLOEXEC`/`SOCK_CLOEXEC`.
`connect_tcp` (1538), the pipes at 10722/6637/7701, the ircd listen and
client sockets are all inheritable. The recorder ffmpeg lives up to 300 s,
the claude CLI for a whole turn, and `/exec` runs arbitrary user commands —
each inheriting the WS TLS socket and the ircd listening socket (a stale
ffmpeg keeps the port bound after shottino exits: "address in use" on
restart).

**Fix:** `SOCK_CLOEXEC` / `O_CLOEXEC` / `pipe2(…, O_CLOEXEC)` at every
creation site, and explicitly clear it for the two fds a child is *meant*
to inherit (the recorder's stdin, the CLI's pipes) after the fork.

### P3.7 — The ircd bridge: three fixes, one commit each

| # | Where | Fix |
| --- | --- | --- |
| a | 13550-13562 | The "no such network X — this account has: …" reply is sent **before** the PASS check at 13566. Move the network-name reply after authentication. |
| b | 13566-13571 | Failed PASS has no rate limit, no delay, no log line, and uses `strcmp`. Add a per-IP failure counter with backoff, log the attempt, and compare in constant time. |
| c | 13946 / 14147 | 8 client slots (`IRCD_MAX_CLIENTS`), no registration or idle timeout: 8 idle pre-auth connections lock the owner out. Reap clients that have not registered within N seconds. |

Loopback binding with no password (14032) is a deliberate tradeoff, but it
hands the whole IRC session to any local user. Consider making it opt-in
(`--ircd-no-password`) rather than the default; discuss before changing,
since it affects every existing invocation.

### P3.8 — Inline media auto-fetches from all hosts by default

**Where:** 14594-14596 — `inline_media_peers = have_ffmpeg`. Whenever
ffmpeg is installed, any URL any stranger posts is fetched when the row
scrolls into view: a working tracking pixel (IP, timing, read receipt) in a
text-only IRC client, plus attacker-chosen bytes into ffmpeg's demuxers.

Mitigated by `-protocol_whitelist` (#451) and a separate process, and
`/media first-party` exists — but the default is the permissive one and the
help text at 14380-14381 implies otherwise.

**Fix:** default `inline_media_peers` to false; keep `/media all` with its
existing warning. Correct the help text either way.

### P3.9 — Token files are created world-readable, then chmod'd

**Where:** `save_token` (3802-3808) and `bot_grants_save` (6826/6836) do
`fopen(path, "w")` — mode `0666 & ~umask` — and `chmod(path, 0600)`
afterwards. `llm_save` (3743) already does it correctly with
`open(O_CREAT, 0600)`, and `prefs_save` (added in `f2ebca7c`) follows
`llm_save`.

**Fix:** copy the `llm_save` shape. One line each, and the correct pattern
is already in the file.

### P3.10 — Fixed multipart boundary, unescaped filename

**Where:** 10307/10309 (upload) and 10465/10471 (STT). The boundary is a
compile-time constant and the body is never scanned for it.

**Fix:** generate a random boundary per request (`RAND_bytes` is already
linked) and escape the filename in `filename="%s"`.

### P3.11 — `json.c` undefined behaviour on hostile numbers

| # | Where | Fix |
| --- | --- | --- |
| a | json.c:659-660 | `d == (double)(long long)d && d < 1e18 && …` performs the cast **before** the range guard: UB for `|d| ≥ 2^63`, Inf, NaN. Reorder to `isfinite(d) && d >= -9.2e18 && d <= 9.2e18` first. Reachable via an LLM tool-call argument re-serialized at llm.c:589. |
| b | json.c:400 | `strtod` overflow unchecked, so `{"x":1e999}` parses as Inf and `json_write` emits `inf`, which is not JSON. Check `errno == ERANGE`. |
| c | json.c:520-524 | `json_long`/`_req`/`_opt` cast an unbounded double to `long` — UB for out-of-range. Reject non-integral / out-of-range in `json_long` itself, which is the one place all three go through. |

Add the malformed-number cases to `tests/test_json.c`; its `numbers` test
currently stops at `1e3`.

### P3.12 — `ircd_tags` accumulates raw `snprintf` returns

**Where:** ircd.c:264-273 — `used += (size_t)snprintf(out + used, out_sz - used, …)`
uses the would-have-written length. On truncation `used > out_sz`, and the
next leg writes at `out + used` with `out_sz - used` wrapped to a huge
`size_t`.

Unreachable today (the only caller passes 128 bytes and the batch ref is
`sh%u`), which is exactly why it should be fixed now rather than after
someone changes a buffer size.

**Fix:** clamp after each `snprintf`. Add the truncation case to
`test_ircd.c:237`, which currently pins only happy paths.

| --- | --- | --- |
| a | 12801 area, `ircd_archive_job` 13504-13512 | The archive reply drops `ircd.lock` between validating the slot id and sending, so a reassigned slot can receive another client's batch. Re-check inside the same critical section as the send. |

## Phase 4 — structure and style

Nothing here changes behaviour. Do it after Phase 1-3, or alongside when
touching the same function anyway.

### P4.1 — Replace the hand-rolled argument parser with `getopt_long`

**Where:** `main`, shottino.c:14468-14553 — three separate pre-scans of
argv (`--mcp-shim`, then `--help`/`-h`, `--version`/`-V`) and an if/else-if
chain of ~11 `strcmp`/`strncmp` arms for 8 options, plus a hand-rolled
`positional[8]` array.

The chain is not spaghetti — options-anywhere and `--ircd=SPEC`-only are
deliberate and commented — but every value-taking option needs **two** arms
(`--login-email` and `--login-email=`) and the space/equals handling is
re-implemented per option.

**Fix:** `getopt_long` is POSIX on both targets (Linux, FreeBSD) and maps
onto the existing semantics exactly:

- the option table becomes data, one entry per option, both spellings for
  free — the same shape `SETTINGS[]` already uses for preferences;
- permutation gives options-anywhere natively, leaving positionals at
  `argv[optind…]`, so `positional[8]` disappears;
- `optional_argument` **enforces** the `--ircd=SPEC`-only rule that is
  currently defended by a comment (an optional value must be attached with
  `=`, never taken from the next slot);
- `-h`/`-V` become ordinary entries instead of a pre-loop.

Keep the `--mcp-shim` pre-scan ahead of everything: that one decides the
process's identity before any UI exists.

Expect ~80 lines to become ~45, and a new option to cost one table row.

### P4.2 — `send_message` is a copy of `send_message_target`

**Where:** 6455-6471 vs 7783-7799 — identical encode/POST/log/free bodies
with the target inlined. The 201-echo behaviour was already patched in both
places once.

**Fix:** `send_message` resolves the focused window and calls
`send_message_target`. (Note: the unlocked `app->windows[…]` read in
`send_message` is P1-adjacent — fix the locking in the same commit.)

### P4.5 — Consistency items

### P4.6 — Test coverage gaps

Not a rewrite — the existing suites are genuinely good (outcome tests, not
mirrors; `test_ws.c` feeds frames a byte at a time; `test_commands.c` scans
the dispatcher's own literals to force the tables to agree). These are the
holes:

- the TLS connect path — `conn_open_to`/`SSL_set1_host`, the security-
  critical hostname binding at 1581, is verified by no test;
- the recording state machine (`/voicemsg`, `/video`, ffmpeg lifecycle,
  `record_cleanup`);
- WS reconnect and backfill orchestration (`ws_backfill_all`);
- panel key handling at 9092 (the renderers are covered, the keys are not);
- the media context menu added in `c6c69ea0` — no test, and never exercised
  against a live pointer.

### P4.7 — Splitting shottino.c: a considered NO

14.7k lines, but organized rather than accreted: ~50 section banners in a
coherent order, and every leaf that *could* be pure is already extracted
(json/wire/ws/llm/media/mirc/termcolor/http/ircd/alias — 5.3k lines with
their own suites). What remains is `struct app`-coupled; a split would need
a `shottino_internal.h` exposing `struct app` plus ~30 shared statics,
buying compile time and no isolation — and `test_commands.c`,
`test_windows.c` and `test_layout.c` `#include "../shottino.c"` directly.

If a split ever happens, the two candidates that would pay are the
downstream ircd bridge (12768-14100, already has its own lock and a clear
boundary) and the /llm+/bot cluster (6476-7480). **Do not split anything
else for its own sake.**
